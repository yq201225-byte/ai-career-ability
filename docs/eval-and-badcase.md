# Eval 与 Badcase

当前回归测试分为三组，每组至少五条：核心路径、关键反例、状态与连续性。完整的本次浏览器执行记录见 [validation-run-2026-09-25.md](validation-run-2026-09-25.md)。

## 核心路径

1. 概念问题在首页先获得直接解释，再进入小测、保存或实操。
2. 模糊学习目标先获得有限追问，再得到轻量下一步。
3. 首页代码解释生成与当前代码相关的五步训练。
4. AI 实操要求用户提交、获得检查、修改后再提交并保存记录。
5. 经历陈述或个人训练案例整理为候选表达，并保存版本快照。

## 关键反例

1. 没有代码上下文时，不生成首页代码训练。
2. 代码第五步不声称代码已运行或可用。
3. 实操中的空泛提交不能直接通过。
4. `写厉害点`、`包装一下`等请求不作为经历内容保存。
5. 高风险“主导”表述不能直接确认用于候选表达。

## 状态与连续性

1. 目标偏好刷新后保留，但不限制模块访问。
2. 学习记录保存后在资产中心可见。
3. 代码理解记录保存后刷新仍可查看理解摘要。
4. 实操案例保存后刷新仍保留个人训练案例标签。
5. 草稿版本、来源快照、删除和撤销状态刷新后正确保留。

## Badcase 处理原则

| 风险 | 产品处理 |
| --- | --- |
| 用户目标模糊 | 先澄清当前需要，不输出大而全计划。 |
| 用户粘贴代码 | 先解释整体作用，再转为结构化训练。 |
| 用户要求夸大表达 | 要求提供具体职责、产物、结果或材料说明。 |
| 用户没有真实项目 | 推荐平台内实操并保存为个人训练案例。 |
| 用户关联截图或链接 | 仅记录材料说明，不认证真实性、相关性或贡献归属。 |
