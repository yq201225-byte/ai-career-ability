# 事实门禁机制

## 为什么需要事实门禁

作品集和简历表达最怕两类问题：一类是把参与写成主导，另一类是把未验证的想法写成已完成结果。AI 生成如果不加约束，很容易把“想表达得好”推向“表达过度”。

因此平台引入事实状态：

- `confirmed`：用户确认且可公开表达的事实。
- `pending`：信息不足，需要继续追问或补证据。
- `rejected`：用户否认或不应进入公开表达的内容。

## 流程

用户选择内容来源（真实经历 / 个人训练案例） -> AI 抽取事实点或读取训练记录 -> 用户确认状态 -> 生成作品集草稿 -> 保存到能力资产中心。

## 规则

- confirmed 可以进入草稿。
- pending 只能生成追问，不进入公开草稿。
- rejected 不进入草稿，也不作为推理依据。
- 涉及隐私、内部资料、不可公开数据时，默认要求脱敏或改为抽象表达。
- 个人训练案例必须保留“个人训练案例”或“独立训练”标签，不能写成上线、团队或工作项目。

## 示例

输入：我参与了一个售后 Agent 项目，效果从 55% 提到 80%。

系统追问：

- 你的角色是什么？
- 样本数量是多少？
- 解决率如何定义？
- 哪些内容可以公开？

只有确认后的事实才进入作品集表达。

训练案例示例：用户完成“AI 知识库问答案例”后，系统只可引用其训练提交、检查结果与复盘，并明确说明它是个人训练案例。
